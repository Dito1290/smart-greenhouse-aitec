================================================================================
E. RISK MITIGATION PLAN
================================================================================

Risk 1: Component procurement delay (shipping, stock issues)
Mitigation:
- Order components dari multiple suppliers
- Identify alternative compatible components
- Buffer time built into schedule (Week 1 procurement + Week 2 buffer)
Contingency: Use Arduino Uno + Ethernet shield sebagai fallback (less optimal)

Risk 2: Sensor inaccuracy atau failure
Mitigation:
- Buy spare sensors (within contingency budget)
- Implement sensor validation checks di firmware
- Cross-verify dengan reference instruments
Contingency: Switch to alternative sensor (DHT22 instead of SHT31, LDR instead BH1750)

Risk 3: Cloud infrastructure issues (VPS downtime, network)
Mitigation:
- Choose reliable VPS provider dengan SLA guarantee
- Implement local data logging ke SD card sebagai backup
- Setup monitoring alerts (UptimeRobot)
Contingency: Switch to alternative MQTT broker (CloudMQTT, HiveMQ free tier)

Risk 4: Greenhouse access restrictions atau unfavorable weather
Mitigation:
- Secure greenhouse location agreement early (Week 1)
- Plan indoor testing environment sebagai alternative
- Weather monitoring untuk schedule outdoor work
Contingency: Use controlled indoor environment (small grow tent) untuk initial testing

Risk 5: Software bugs atau integration issues
Mitigation:
- Incremental development dengan frequent testing
- Version control dengan Git untuk easy rollback
- Allocate buffer time di schedule (Week 7 untuk bug fixing)
Contingency: Reduce feature scope to MVP (remove supplemental lighting, keep core monitoring/irrigation)
