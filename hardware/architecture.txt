CHANNEL ASSIGNMENT:
- Relay 1 (CH1): Water Pump 12V DC
- Relay 2 (CH2): Exhaust Fan 12V DC

CATATAN PENTING:
- ESP32 GPIO output 3.3V, tetapi relay module umumnya 5V trigger
- Solusi: Gunakan level shifter ATAU pilih relay module 3.3V compatible
- Alternatif: Relay module dengan jumper untuk 3.3V/5V selection

Load Calculation:
- Water Pump: 12V x 0.8A = 9.6W
- Exhaust Fan: 12V x 0.2A = 2.4W
- LED Grow Light: 12V x 1.5A = 18W
- ESP32 (via step-down): 5V x 0.5A = 2.5W
- Total Peak: ~33W → 3A @ 12V sufficient

B. Step-Down Converter (Buck Converter) 12V → 5V

CONTROL ALGORITHM - Hysteresis Example (Soil Moisture):

Target Soil Moisture: 70%
Hysteresis Band: ±5%

IF soil_moisture < 65%:
    pump_state = ON
ELSE IF soil_moisture > 75%:
    pump_state = OFF
ELSE:
    pump_state = MAINTAIN (no change)

Rationale: Mencegah rapid cycling relay yang dapat shorten lifespan


--------------------------------------------------------------------------------
3.2 MQTT TOPIC STRUCTURE
--------------------------------------------------------------------------------

PUBLISH Topics (ESP32 → Cloud):

greenhouse/[device_id]/sensors/temperature      → float (°C)
greenhouse/[device_id]/sensors/humidity         → float (%)
greenhouse/[device_id]/sensors/soil_moisture    → float (%)
greenhouse/[device_id]/sensors/light_intensity  → int (lux)
greenhouse/[device_id]/actuators/pump           → bool (0/1)
greenhouse/[device_id]/actuators/fan            → bool (0/1)
greenhouse/[device_id]/actuators/light          → bool (0/1)
greenhouse/[device_id]/status/online            → string (timestamp)
greenhouse/[device_id]/status/wifi_rssi         → int (dBm)
greenhouse/[device_id]/status/uptime            → int (seconds)

SUBSCRIBE Topics (Cloud → ESP32):

greenhouse/[device_id]/commands/pump            → "ON" | "OFF" | "AUTO"
greenhouse/[device_id]/commands/fan             → "ON" | "OFF" | "AUTO"
greenhouse/[device_id]/commands/light           → "ON" | "OFF" | "AUTO"
greenhouse/[device_id]/config/thresholds        → JSON config update
greenhouse/[device_id]/config/intervals         → JSON timing update
greenhouse/[device_id]/system/restart           → trigger system reboot
greenhouse/[device_id]/system/ota               → trigger OTA update


PAYLOAD FORMAT (JSON):

Example - Sensor Data Publish:
{
  "timestamp": "2026-09-29T07:45:23Z",
  "device_id": "greenhouse_001",
  "temperature": 26.5,
  "humidity": 72.3,
  "soil_moisture": 68.4,
  "light_intensity": 25000,
  "pump_state": 0,
  "fan_state": 1,
  "rssi": -65
}


--------------------------------------------------------------------------------
3.3 CLOUD BACKEND ARCHITECTURE
--------------------------------------------------------------------------------

STACK:
- OS: Linux Ubuntu 22.04 LTS
- MQTT Broker: Eclipse Mosquitto 2.x
- Database: InfluxDB 2.x (time-series data)
- API Server: Node.js 18.x + Express.js
- Process Manager: PM2

COMPONENTS:

A. MQTT Broker (Mosquitto)
   - Port 1883 (MQTT) dan 8883 (MQTTS with TLS)
   - Authentication: username/password atau client certificates
   - Bridge mode untuk multi-site deployment (future)

B. Data Ingestion Service (Node.js)
   - Subscribe to all greenhouse/+/sensors/# topics
   - Parse JSON payload
   - Write to InfluxDB dengan proper tags/fields
   - Handle data validation dan error logging

C. RESTful API Server (Express.js)
   - GET /api/devices → List all registered greenhouses
   - GET /api/devices/:id/latest → Latest sensor readings
   - GET /api/devices/:id/history?start=&end= → Historical data
   - POST /api/devices/:id/command → Send control command
   - GET /api/analytics/summary → Dashboard summary statistics
   - Authentication: JWT token-based

D. InfluxDB Schema
   Measurement: greenhouse_sensors
   Tags: device_id, location (future multi-site)
   Fields: temperature, humidity, soil_moisture, light_intensity,
           pump_state, fan_state, light_state
   Timestamp: Unix epoch nanoseconds

NETWORK REQUIREMENTS:
- ESP32 → MQTT Broker: Stable WiFi, ~1 KB/min data transfer
- Latency: <500ms untuk command response (local network)
- Bandwidth: Minimal (~10 KB/hour per device)
- Reliability: MQTT QoS 1 (at least once delivery) untuk critical commands


SECURITY CONSIDERATIONS:
1. MQTT Authentication: Username/password minimum, TLS/SSL preferred
2. Dashboard: HTTPS only, JWT token dengan expiration
3. API: Rate limiting, input validation, SQL injection prevention
4. ESP32: No hardcoded credentials (use EEPROM atau SPIFFS config file)
5. Network: Firewall rules, close unnecessary ports, VPN untuk remote access
